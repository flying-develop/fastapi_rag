# Базовые правила проекта

> Новый проект без существующего кода — ниже зафиксированы стартовые
> конвенции на основе выбранного стека (Python 3.12+, FastAPI,
> SQLAlchemy 2.0, LangChain/LangGraph). Правь по мере появления кода.

## Соглашения об именовании

- Файлы и модули: `snake_case.py`
- Переменные и функции: `snake_case`
- Классы (модели, сервисы, схемы, DTO): `PascalCase`
- Константы: `UPPER_SNAKE_CASE`
- Pydantic-схемы запросов/ответов: суффиксы `Request`/`Response`
  (например, `DialogMessageCreateRequest`)

## Структура модулей

Архитектура — Structured Modules (Technical Layer), подробности в
`.ai-factory/ARCHITECTURE.md`. Каждый домен — отдельный модуль в
`app/modules/<module>/`:

- `app/modules/<module>/api/` — роуты FastAPI (только валидация
  входа, вызов сервиса, формирование ответа; без бизнес-логики и без
  прямых обращений к БД)
- `app/modules/<module>/services/` — бизнес-логика модуля, включая
  LangChain/LangGraph цепочки и графы
- `app/modules/<module>/repositories/` — единственная точка доступа к
  БД модуля через SQLAlchemy; прямые вызовы `session.execute`/raw SQL
  вне этого слоя запрещены
- `app/modules/<module>/models/` — SQLAlchemy ORM-модели модуля
- `app/modules/<module>/schemas/` — Pydantic-схемы (DTO) модуля
- `app/infrastructure/` — сквозная инфраструктура: конфигурация,
  инициализация БД/Redis/Qdrant/LLM-клиентов, логирование, обработка
  ошибок; без бизнес-логики и без специфики отдельного модуля

Межмодульное взаимодействие — только через сервисы другого модуля
(публичный интерфейс), не через его репозитории или модели напрямую.

## Обработка ошибок

- Единый формат ошибок API — доменные исключения перехватываются
  централизованным exception handler'ом FastAPI и превращаются в
  структурированный JSON-ответ
- Доменные ошибки — через собственные классы исключений с явным
  кодом ошибки, а не через общие `Exception`/`ValueError` без контекста

## Контроль потока выполнения

- Предпочитать плоский, читаемый control flow вместо глубокой
  вложенности условий: guard clauses, ранние `return`/`continue`,
  небольшие именованные хелпер-методы или явную классификацию.
  Обрабатывать граничные случаи и нерелевантные ветки в начале
  функции, чтобы основной путь оставался на виду.

## Логирование

- Структурированное логирование, уровень настраивается через
  переменную окружения `LOG_LEVEL`
- Стандартный модуль `logging` с JSON- или key=value-форматтером;
  не использовать `print()` в прикладном коде
