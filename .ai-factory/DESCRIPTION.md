# AI-сервис

## Обзор

AI-сервис на стеке FastAPI + LangChain/LangGraph: RAG по статьям,
диалоги с LLM, конвейер модерации контента (профили, аватары, файлы,
сообщения, "хочу" от клиентов) и очереди фоновой обработки задач.
Сервис развивается поэтапно — от простого ядра к сложным сценариям.

## Ключевые возможности (появляются поэтапно)

- **Диалоги с LLM** — чат-сессии (`Dialog`/`DialogMessage`), пошаговые
  ответы ассистента с сохранением истории.
- **Tool calling у LLM** — модель вызывает инструменты-функции
  (structured output), параметры и результат описаны Pydantic-
  схемами, а не парсятся из свободного текста. Сквозной паттерн:
  сначала осваивается на простом примере, затем переиспользуется как
  способ получения данных (запросы к БД, RAG-поиск, вызовы внешних
  API) и реализации других фич поверх LangChain/LangGraph.
- **RAG по статьям** — индексация статей (chunking → embedding →
  upsert в векторную БД), поиск релевантных чанков, rerank,
  формирование ответа с источниками.
- **Обработка задач (Task pipeline)** — асинхронный конвейер с
  состояниями и шагами (`Task` → `TaskStep` → `TaskResult`),
  аналог очереди с ретраями и колбэками о результате.
- **Модерация контента** — несколько независимых конвейеров модерации
  (профиль, аватар, обложка профиля, файлы профиля, сообщения,
  "хочу"-заявки) на базе LLM-классификации с кодами ошибок.
  Начинаем с одного упрощённого конвейера как референса, остальные —
  на следующих этапах.
- **Работа с файлами** — приём, парсинг (PDF/DOCX/XLSX → текст),
  хранение (S3-совместимое хранилище).
- **API-ключи и контексты доступа** — разграничение доступа внешних
  клиентов сервиса по ключам и контекстам.

## Технологический стек

- **Язык:** Python 3.12+
- **Веб-фреймворк:** FastAPI
- **AI-оркестрация:** LangChain (компоненты, chat-модели, embeddings) +
  LangGraph (графы состояний для диалогов и task pipeline)
- **База данных:** PostgreSQL
- **Доступ к БД:** SQLAlchemy 2.0 (async) + Alembic для миграций
- **Векторная БД:** Qdrant, интеграция через `langchain-qdrant`
- **Фоновые задачи / очереди:** ARQ + Redis (asyncio-нативная очередь
  задач с ретраями)
- **LLM-провайдер:** OpenAI на первых этапах через единый интерфейс
  LangChain chat-моделей (архитектура должна допускать добавление
  Gemini/Qwen позже без переписывания вызывающего кода — провайдер
  конфигурируется через `.env`)
- **Управление пакетами:** uv
- **Тестирование:** pytest (+ pytest-asyncio)

## Архитектура

Подробные гайдлайны — в `.ai-factory/ARCHITECTURE.md`.
Паттерн: **Structured Modules (Technical Layer)**.

- Каждый домен (диалоги, RAG, task pipeline, модерация, файлы) —
  отдельный модуль в `app/modules/<module>/` со своими
  `api/services/repositories/models/schemas`.
- Внутри модуля — строгий поток `api → services → repositories`,
  прямого доступа к БД из сервисов или роутов быть не должно.
- Конвейеры модерации и RAG-обработка реализуются как графы LangGraph
  (узлы = шаги конвейера, рёбра = переходы состояний) — состояния и
  переходы конвейера моделируются явной state machine.
- Сквозная инфраструктура (БД, Redis, Qdrant, LLM-клиенты, конфиг,
  логирование) — в `app/infrastructure/`, без бизнес-логики.
- Конфигурация провайдеров (LLM, embeddings, БД, Redis, Qdrant, S3)
  — через переменные окружения (`.env`).
- Проект развивается поэтапно через `/aif-roadmap` и `/aif-plan`:
  сначала минимальный сквозной сценарий (один диалог с LLM, одно
  простое сохранение в БД), затем RAG, затем task pipeline и
  модерация.

## Нефункциональные требования

- **Логирование:** структурированное, настраивается через `LOG_LEVEL`.
- **Обработка ошибок:** единый формат ошибок API, явные коды ошибок
  для доменных сбоев (модерация, RAG, PII).
- **Безопасность:** секреты и API-ключи только через переменные
  окружения, не коммитятся в репозиторий; валидация входных данных
  на границе API через Pydantic-схемы.
- **Асинхронность:** весь I/O (БД, LLM-вызовы, Redis, Qdrant, S3)
  — через async/await, без блокирующих вызовов в event loop.
- **Окружение разработки:** локально всё поднимается через Docker /
  docker-compose (сервис на FastAPI, PostgreSQL, Redis, Qdrant) —
  без установки зависимостей и БД напрямую на хост-машину.
  Конфигурация Docker создаётся отдельным этапом через
  `/aif-dockerize`.
